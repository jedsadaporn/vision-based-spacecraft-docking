# 7.8 Discussion & Limitations

## 7.8.1 What Was Demonstrated

The project demonstrated an end-to-end closed-loop spacecraft docking pipeline in a simplified simulation environment.

The system integrates:

- Camera/image input
- Synthetic target detection
- Relative state/error estimation
- Proportional control
- Simulated spacecraft state updates
- Docking-condition detection
- Experiment logging
- Result analysis and visualization

All three controlled test cases successfully reached the defined docking condition. The position error magnitude decreased over time in all three trials, indicating that the proportional controller drove the simulated spacecraft state toward the docking target.

## 7.8.2 Limitations

### Simplified Spacecraft Motion Model

The spacecraft motion model is simplified and does not represent full spacecraft dynamics or orbital mechanics. The current simulation uses simplified translational state updates rather than a physical 6-DoF spacecraft model.

### Simplified Perception

The perception system uses a synthetic target and simplified image processing rather than a realistic spacecraft camera and docking target.

Therefore, the current experiment does not evaluate robustness to image noise, lighting changes, occlusion, camera calibration errors, detection failures, or realistic target appearance.

### Fixed Controller Gain

The experiments use a fixed proportional gain of `Kp = 0.2`.

Therefore, the current results do not evaluate controller tuning, different proportional gains, controller stability across a range of conditions, or alternative controllers.

### Limited Number of Experiments

Only three controlled test cases were evaluated.

The results are useful for demonstrating system behavior and validating the MVP pipeline, but they are not sufficient to make broad statistical conclusions about docking performance.

### Simplified State and Units

The current state representation uses simplified `x`, `y`, and `z` quantities. Their physical interpretation and units are limited by the simplified simulation model.

The reported position-error values should therefore be interpreted within the context of this simulation rather than as flight-validated physical measurements.

## 7.8.3 Scope of the Results

The results should be interpreted as an engineering validation of the MVP pipeline rather than a validation of a flight-ready autonomous spacecraft docking system.

The project demonstrates the intended MVP workflow:

> Camera → Target Detection → Relative State Estimation → Controller → Spacecraft Motion → Docking Evaluation

Additional modeling, sensing, estimation, control, and validation would be required before making claims about realistic spacecraft docking performance.

## 7.8.4 Future Extensions

Research-grade extensions can be considered after the MVP has been completed and packaged.

Potential future work includes:

- Realistic 6-DoF spacecraft dynamics
- Real camera hardware or a more realistic camera simulation
- Camera calibration
- 6-DoF pose estimation using PnP
- Kalman/EKF-based state estimation
- Sensor noise modeling
- Measurement latency modeling
- Disturbance modeling
- Controller tuning and comparison
- Larger-scale statistical evaluation
- Monte Carlo experiments
- More realistic docking scenarios

These extensions are intentionally outside the current MVP scope.
